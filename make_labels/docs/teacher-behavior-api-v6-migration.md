# 新版教师行为接口迁移契约

> 状态：已评审，待实施。本文件只定义后续改造口径；当前代码仍使用旧版映射和处理逻辑。

## 结论

标签制作的整体流程不变，仍然是“ImageDetect 初检 + 中文标注图 + VLM 复核 + YOLO 写入”。新版接口已经能输出 `204=讲授`，但该结果只是初检候选，不应直接作为最终训练标签：VLM 仍需结合画面确认讲授是否真实发生，并可删除误检或补充漏检。

新版不能只替换请求地址。教师类别编码、主体框来源和空框语义都发生了变化，必须按本文件整体切换。

## 接口边界

- 路由保持为 `POST /ImageDetect/teacher/v1.0.0`。
- 服务基地址和端口由本地 `config.toml` 注入，不硬编码到源码或公开样例。随附接口文档只固定路由并说明端口以实例配置为准；`8871` 来自本次目标环境的部署信息，实施时仍需先确认实际地址和可达性。
- 请求图片继续使用 `ImageList[].StoragePath`，支持带 MIME 前缀的 Base64；`ImageId` 必须唯一并与响应逐图匹配。
- 新版请求可增加 `task_id`、`batch_id`、`stream_type="teacher"`、`ReturnHeadPose` 和 `Teacher_Behavior_Thresd`，但它们不是完成本次标签迁移的前置条件。

## 类别差异

| `ObjectType` | 当前项目的旧语义 | 新版教师语义 | 内部标签 | 中文展示 |
| ---: | --- | --- | --- | --- |
| `100` | 只按数量判断讲台有人，不使用框 | 主教师主体框 `platform_person` | 不生成类别 | 不作为行为展示 |
| `201` | 站立 | 坐着 `sitting` | `sit` | 坐着 |
| `202` | 坐着 | 站立 `standing` | `stand` | 站立 |
| `203` | 板书 | 板书 `writing` | `bbwriting` | 板书 |
| `204` | 旧接口为老师使用手机，当前项目忽略 | 讲授 `teaching` | `teach` | 讲授 |
| `205` | 授课 | 新版教师接口不再定义 | 契约错误 | 不展示 |

注意：以上仅是教师接口映射，不能套用到学生接口。现有代码中的 `201=stand`、`202=sit`、`205=teach` 必须一次性切换，避免生成语义相反的标签。新版响应若仍出现 `205`，视为服务契约版本不匹配：保留原始响应并终止该图片的标签生成，不静默忽略，也不把它解释成 `teach`。

## 目标数据流

```text
原始教师画面
  -> 调用新版 ImageDetect
  -> 校验 HTTP、根级状态和单图状态
  -> 读取 ObjectType=100 的主教师主体框
  -> 汇总该主体的全部初检行为 201/202/203/204
  -> 在主体框上方绘制全部中文标签
  -> 将完整中文标注图交给 VLM 复核
  -> VLM 保留、删除或补充行为，并给出 needs_review
  -> 使用 ObjectType=100 的主体框和 VLM 最终标签写入 YOLO
```

例如，同一图片返回主教师框，并命中 `202`、`203`、`204`，预览图的框上方必须完整显示：

```text
站立 | 板书 | 讲授
```

不能只显示其中一个标签，也不能继续使用英文、`+` 分隔符或“授课”作为 `204` 的展示文字。标签必须位于框上方；水平空间不足时换行或缩小字号，顶部空间不足时只对送给 VLM 的预览图增加顶部画布，不能把标签移入主体框、遮挡主体或裁掉文字。新增画布只用于展示，最终 YOLO 坐标仍按原图尺寸和 `100` 主体框计算。

## 解析规则

### 状态校验

1. HTTP 非成功状态不能当作“没有检测结果”。
2. 根级 `StatusObject.StatusCode` 必须为 `0`。
3. 每张图片的 `StatusObject.StatusCode` 必须为 `0`，且 `ImageId` 必须匹配请求。
4. `DataList` 缺图、重复 `ImageId`、状态对象缺失或响应 JSON 非法都应记为检测失败，不得静默过滤为无行为样本。

### 主体框

- 最终 YOLO 框以 `ObjectType=100` 的有效 `ObjectPostList` 为准，不再从行为框按 IoU 合并后猜测主体。
- 正常响应应只有一个主教师主体。若出现多个有效框，逐框读取 `ResultList[ObjectType=100].ObjectPostList[].Confidence`，按“有效数值置信度降序、框面积降序、原始列表索引升序”稳定选择；缺失或非数值置信度按最低值处理。出现多个有效框时无论选择结果如何都设置 `needs_review=true`，并保存全部原始框及索引。若部署实例把 `Confidence` 放在其他层级，先通过 fixture 更新契约再实施，不能猜测字段来源。
- `ObjectType=100` 只有数量但没有有效框时，不能生成 YOLO 标签；该图片应进入失败或人工复核流程，不能用任意行为框静默替代。

### 行为汇总

- 在同一个单图结果中，以 `ObjectCount>0` 判断 `201-204` 行为命中，并将它们关联到 `100` 主教师主体。
- 行为项的 `ObjectPostList` 允许为 `null` 或空数组。新版服务已在上游合并同一主体，不能因为行为项没有框就丢弃“板书”或“讲授”。
- `ObjectPostList` 一律按 `item.get("ObjectPostList") or []` 兼容；`Confidence`、`SuspectedSitting`、`PostureFallback` 均为可选字段。
- 若 `ObjectCount` 与非空框列表矛盾，保存原始值并设置 `needs_review=true`，不要自行篡改检测结果。
- 若同时命中坐着和站立，预览图应如实展示两个初检标签，交由 VLM 决策，并强制 `needs_review=true`。
- `SuspectedSitting=true` 或 `PostureFallback=true` 表明姿态存在冲突或回退，最终结果必须进入人工复核。

## VLM 复核契约

VLM 输入是包含完整场景、`100` 主体框和全部中文初检标签的图片。提示词必须说明初检标签只是候选，要求模型基于视觉内容独立复核，而不是照抄框上的文字。

最终规则保持为：

- `sit` 与 `stand` 互斥且必须二选一。
- `bbwriting` 和 `teach` 可独立存在，也可同时存在。
- ImageDetect 命中 `204`，但画面没有明显讲解、表达或授课动作时，VLM 应删除 `teach`。
- ImageDetect 未命中 `204`，但画面有明显讲授行为时，VLM 可以补充 `teach`。
- “老师站立板书讲授”应输出 `stand + bbwriting + teach`。
- 背对学生且只在书写时保留 `bbwriting`，不因为新版返回 `204` 就强制保留 `teach`。
- 视觉证据不足、坐站冲突、检测与 VLM 结论冲突或使用姿态回退时，设置 `needs_review=true`。

VLM 输出继续使用当前结构，以减少迁移范围：

```json
{
  "labels": ["stand", "bbwriting", "teach"],
  "needs_review": false,
  "reason": "老师站立面向课堂，边板书边讲解"
}
```

最终 YOLO 标签只能来自 VLM 解析后的 `labels`，不能直接用 ImageDetect 的 `ObjectType` 写盘。

## 可追溯元数据

每张样本至少保留以下信息：

- 接口契约版本或适配器版本。
- 根级和单图 `StatusObject`。
- `100` 主体原始框、所选主框及其 `Confidence`。
- 每个行为的原始 `ObjectType`、`ObjectCount`、`ObjectPostList`、`Confidence`、`SuspectedSitting` 和 `PostureFallback`。
- 初检英文标签、中文标签及其固定顺序。
- 送给 VLM 的预览图或可复现该图的信息。
- VLM 原始响应、解析后的最终标签、理由和 `needs_review`。

现有 `source_8881_labels` 和 `source_8881_object_types` 可在过渡期保留，但新增字段应使用与端口无关的 `source_detector_*` 命名，避免接口再次迁移时产生歧义。

## 重试与失败处理

- HTTP `2xx` 才进入 JSON 和业务状态校验；其他状态按下述规则处理。
- `429`、`500`、`503`、网络连接错误和超时最多发起 3 次请求，即首次请求加 2 次重试。
- 第 1、2 次失败后的默认等待分别为 `1` 秒、`2` 秒，各加入 `0-0.5` 秒随机抖动。响应带可解析的秒数型 `Retry-After` 时优先采用该值，但单次等待上限为 `30` 秒。
- `422` 属于请求契约错误，不重试，应立即暴露请求体问题。
- 其他 HTTP `4xx` 不重试。根级或单图 `StatusCode != 0` 属于业务失败；因随附文档未定义可重试业务码，当前不自动重试。
- 3 次请求仍失败时保存不含图片 Base64 和凭据的响应摘要，并进入失败流程。
- 日志不得记录图片 Base64、真实密钥或带认证参数的完整视频 URL。

## 实施范围

后续实现需同步修改两条标签制作链路，避免主服务和离线脚本产生不同语义：

- `app/detector.py`：新版映射、状态校验、`100` 主体框和行为汇总。
- `app/imaging.py`：在框上方绘制按固定顺序排列的中文标签。
- `app/vlm_labeler.py`：明确 VLM 对初检标签的保留、删除和补充职责。
- `app/pipeline.py`：使用主体框、传递完整初检元数据并区分检测失败和无行为。
- `scripts/teacher_vlm_labeler.py`：与主服务使用同一契约和展示口径。
- `config.example.toml` 与 README：更新中性的服务配置命名和运行说明。

当前文档提交不修改上述代码，也不切换生产或联调地址。

## 回归测试清单

- 新版响应 fixture：`100` 主体框 + `202/203/204` 命中且行为框为 `null`，解析得到 `stand/bbwriting/teach` 初检候选；模拟 VLM 保留后，最终标签仍为 `stand/bbwriting/teach`。
- 映射测试：`201=sit`、`202=stand`、`203=bbwriting`、`204=teach`；`205` 触发契约版本不匹配且不生成样本。
- 主体框测试：最终框来自 `100`，不再选择行为框。
- 中文渲染测试：`站立 | 板书 | 讲授` 全部出现且始终位于框上方；空间不足时换行、缩小字号或增加预览顶部画布，文字不越界且 YOLO 坐标仍基于原图。
- VLM 测试：可删除误检 `teach`，也可补充漏检 `teach`。
- 冲突测试：坐着和站立同时命中、`SuspectedSitting` 或 `PostureFallback` 会触发 `needs_review`。
- 兼容测试：`ObjectPostList=null`、缺少可选 `Confidence`、空 `ResultList`。
- 状态测试：根级失败、单图失败、缺图和重复 `ImageId` 均不会被当作普通无结果。
- 重试测试：`429/500/503`、连接错误和超时最多总计 3 次请求；`Retry-After` 不超过 30 秒；`422`、其他 `4xx` 和业务状态失败不重试；耗尽后保留可诊断错误。
- 端到端测试：同一 `100` 框以 VLM 最终多标签写出多行相同坐标的 YOLO 标签。

## 验收标准

1. 对“老师站立板书讲授”样例，初检预览显示 `站立 | 板书 | 讲授`。
2. VLM 能分别保留、删除和补充 `teach`，最终标签不与初检结果强绑定。
3. YOLO 坐标始终来自 `100` 主教师框，标签始终来自 VLM 最终结果。
4. 新旧编码不会在同一运行配置中混用，并能从元数据识别使用的契约版本。
5. 所有 fixture 和现有测试通过后，才允许切换目标实例。
